Ethics and public-API-only policy

AxiomChess analyzes finished games using engine-backed features and a calibrated suspicion score with uncertainty. It is an educational analysis aid, not a tribunal. Reports never output a definitive guilt label.

On this page

  1. Hard rules
  2. Lichess
  3. Chess.com
  4. Report integrity
  5. UI and copy requirements
  6. Adding another site

Hard rules

  1. Use only documented public endpoints and user-supplied or public PGNs.
  2. Lichess: official public API at https://lichess.org only. Respect one-request-at-a-time guidance; after HTTP 429 wait at least one minute before retry (per Lichess API tips).
  3. Chess.com: Published-Data API base https://api.chess.com/pub/ only. Public read-only data; no private chat, conditional moves, or authenticated-only surfaces.
  4. Include another site only when a legal public route or standard public PGN export is documented. If none exists, do not add an adapter.
  5. No account takeover, no captcha bypass, no private game access, no ToS evasion.
  6. Reports must present uncertainty. Never output a definitive guilt label without a clear confidence band and methodology note.
  7. Prefer analyzing a player's own games or clearly public games. UI copy must state limits and false-positive risk.

These rules are non-negotiable for first-party code and for documentation examples. Demo scripts must not teach private-game scraping.

Lichess

Official docs: https://lichess.org/api. Tips: https://lichess.org/page/api-tips.

  • Export user games and single-game export endpoints as documented in the official OpenAPI.
  • Throttle: one request at a time from a worker; on 429 wait at least 60 seconds before retry.
  • CI and unit tests use recorded fixtures; no live network required for green builds.

Chess.com

Published-Data API announcement and docs govern the base https://api.chess.com/pub/. Archives list, monthly games JSON, and monthly PGN paths are used as documented. PubAPI has no single-game endpoint; AxiomChess composite ids use username/YYYY/MM/id from list results.

Report integrity

  • Bands only: low, elevated, high, inconclusive.
  • Always attach methodology note, policy id, false-positive warning, and sample-size caveats.
  • Do not change calibration cut points to make fixtures pass; cut a new policy version instead.

See Methodology and Scoring bands.

UI and copy requirements

  • English only. No emoji.
  • Clear errors for private_or_unavailable and rate_limited.
  • No copy that encourages private-game access.
  • Landing and report surfaces must keep brand-first, anti-slop visual rules from the design system.

Adding another site

Implement SiteAdapter with fixtures, allowlisted hosts, and documented public access only. Register in the adapters manifest consumed by GET /v1/sites. If a site has no legal public route, do not ship an adapter.
