Pipeline detail

  1. Ingest URL | ID | username | PGN
  2. Normalize to canonical PGN + metadata
  3. Engine eval (MultiPV, depth policy)
  4. Features (match, CPL, timing if available, opening novelty)
  5. Calibrated score + explanation
  6. JSON result + human report

Stack

  • TypeScript throughout
  • API: Hono + @hono/node-server on Node 20+
  • Web: Next.js App Router + React + Tailwind
  • Engine: official Stockfish (GPL) as external UCI process
  • DB: PostgreSQL
  • Queue/cache: Redis optional; single-node in-memory fallback
  • Package manager: pnpm per repo

Data stores

Postgres holds analyses, API key hashes, and schema migrations. Retention purge removes expired rows. Redis, when configured, backs rate limits and optional job queue depth.

Observability

Structured JSON logs and in-process metrics (request counts, queue depth, engine durations, cache hit/miss, upstream 429). requestId on the HTTP path. Info logs prefer PGN content hashes over raw PGN.
